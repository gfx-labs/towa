# An item's body is one interface value

Date: 2026-11-13

## What changed

`transcript.Item` had ten pointer fields (`User`, `Text`, `Thinking`, `ToolCall`, `ToolResult`, `Native`, `Usage`, `ModelSwitch`, `Compaction`, `Interrupted`) of which exactly one had to be set. Nothing but `Validate` enforced that, and every reader was a chain of nil checks.

It now has one field for that, `Body`, of the interface type `transcript.Body`. The ten types implement it with an unexported method, so no other package can add an eleventh. `Provider`, `Opaque` and `Origin` stay on `Item`.

```go
type Item struct {
	Body     Body
	Provider string
	Opaque   jsontext.Value
	Origin   *Origin
}
```

A generic `Item[B]` was considered and does not fit: a transcript is one slice of mixed items, and `Item[User]` and `Item[Text]` would be different types.

What follows from it:

- An item with two bodies cannot be written. `Validate` still rejects an item with none, and a body held by pointer, which no type switch would match.
- Readers are type switches (`switch body := item.Body.(type)`), or `transcript.Is[transcript.Compaction](item)` where only the kind matters.
- A body is a value, so changing one means assigning a new one to `item.Body`. The loop's history code already copied before changing; now the compiler requires it.
- The stored form is the same: an object with one member named after the body, beside `provider`, `opaque` and `origin`. `Item` has `MarshalJSONTo` and `UnmarshalJSONFrom` for that, since `encoding/json` cannot decode into an interface. Decoding an object with no body member or with two is an error. `TestItemIsStoredUnderItsBodysName` covers every body.
- `gochecksumtype` is enabled in `.golangci.yml` with `default-signifies-exhaustive`. A switch over bodies must list all ten or have a `default`. Turning it on found twelve switches that handled some bodies and silently passed the rest. Each now has either the remaining cases or a `default`, with a comment saying why those are passed over. No behaviour changed.

## Measurements

`unsafe.Sizeof`, before and after:

| Type | Before | After |
|---|---|---|
| `transcript.Item` | 128 bytes | 64 bytes |
| `transcript.Entry` | 184 bytes | 120 bytes |

The body itself is now a separate allocation where it used to be pointed to anyway, so the count of allocations for an item is the same. No turn was profiled for this change: it is a change of representation, and the sizes are the only numbers taken.

51 files: `src/transcript`, the three provider clients and `hostedsearch`, `src/agent/loop`, `src/prompt/compact`, `src/tools/convsearch`, `src/tools/todo`, `src/store/dir`, and their tests.
