# Auth lane: account store, refresh, proxied accounts, login

2026-11-11

## What was built

- `src/auth/store.go`: `Store`, one file per account, `<dir>/<account>.json`. The directory is made 0700 and a file 0600. `Save` writes a temp file in the same directory, syncs it and renames it. `Load` refuses a file that group or others can read. `StateDir` gives `$XDG_STATE_HOME/towa/auth`, or `$HOME/.local/state/towa/auth`, and is an error when neither variable is set.
- `src/auth/flock_linux.go`, `flock_darwin.go`: `unix.Flock(LOCK_EX)`, retried on `EINTR`.
- `src/auth/source.go`: `AccountSource` implements `auth.Source` over `config.Accounts`.
- `src/auth/oauth.go`: `Flow` (the endpoints, client id, scopes and request shape of one provider), `ClaudeFlow`, `CodexFlow`, PKCE, the code exchange and the refresh grant.
- `src/auth/login.go`: `RunLogin`, the browser login with a local callback server and the manual login with a pasted code.
- `src/auth/browser_linux.go`, `browser_darwin.go`: `xdg-open` and `open`.
- `src/cli/login.go`: `accountCommands(h Host) []*cli.Command` with `login <provider> --account <id> [--manual]`, `logout --account <id>` and `accounts`.
- `src/config/accounts.go`: the `auth` section, `Account.ChatGPTAccountID`, and a check that an account id is a plain file name.

## Decisions

- **The lock is on `<account>.lock`, not on `<account>.json`.** The design says "an `flock` on the account file". `Save` replaces that file by rename, so a process that locked the old inode excludes nobody who opens the new one. The lock file is never removed, for the same reason. `docs/design.md` should say "the account's lock file".
- **A fresh token takes no lock.** `Credential` reads the file, and only a token inside the refresh margin goes to the lock. The rename makes the unlocked read safe.
- **Refresh after a rejection.** `Refresh(rejected)` takes the lock and re-reads. It keeps the stored token only when it differs from the rejected one and is fresh. So several callers holding the same refused token cause one request.
- **The refreshed token is saved without the caller's context.** The endpoint has already replaced the refresh token by then. Losing the write to a cancelled turn would lose the login.
- **A failed refresh leaves the file alone.** The error is a `*auth.TokenError` with the status and the endpoint's `error` member. Nothing records "this refresh token is dead", so every later call tries again. jcode keeps such a record (`refresh_state`). Not built.
- **Proxied accounts.** The placeholder is `towa-proxied-<account>`. `Refresh` returns `auth.ErrProxied`. `login` and `logout` return the same error before any request.
- **`api_key`.** An unset variable is `auth.ErrNoKey`. `Refresh` returns `auth.ErrStaticKey`.
- **The stored file names its provider.** A file is not used for an account that the config has since given to another provider.
- **State.** Every login has a random state of its own, checked on the callback and on a pasted code. jcode sends the PKCE verifier as the Claude state, which puts the verifier in the browser's address bar. The Claude token endpoint is sent the state in the JSON body, as jcode does.
- **A pasted code needs its state.** A bare code is refused. Claude's page shows `code#state`. For Codex the user pastes the whole address.
- **No silent fallback from browser to paste.** If the port cannot be bound, no browser opens or the callback times out, `login` fails and names `--manual`. jcode falls back on its own.
- **`logout` deletes the file and revokes nothing.** jcode's source names no revocation endpoint.
- **No dependency added.** `golang.org/x/sys` was pinned already.

## The ChatGPT account header

jcode sends `chatgpt-account-id` on Codex backend requests when it has an account id, and leaves the header out when it has none (`openai_stream_runtime.rs:428`). Its source does not say whether the backend refuses a request without it. That needs a live request to answer and none was made.

A harness-held account gets the id at login and at each refresh that returns an id token: the claim `chatgpt_account_id` under `https://api.openai.com/auth` in the id token's payload. It is stored in the account file and put in `Credential.ChatGPTAccountID`. A Codex login whose id token has no such claim is an error.

A `proxied_oauth` account has no id token, so its id is the config key `accounts[].chatgpt_account_id`. It may be empty, and then the credential carries none.

## Checks

Run on Linux, Go 1.27.3:

```
nice -n 10 go test -race -count=1 ./src/auth/ ./src/config/ ./src/cli/
nice -n 10 golangci-lint run ./src/auth/... ./src/config/... ./src/cli/...
GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./src/auth/... ./src/cli/...
CGO_ENABLED=0 go build ./src/auth/... ./src/cli/...
```

- `TestProcessesShareOneRefresh`: 12 processes (the test binary run again) and 12 goroutines ask for the same expired account at once, against a local token endpoint that takes 200 ms, counts requests and refuses a refresh token used twice. Result: 1 request, 0 refusals, all 24 got the new token. It also checks the directory is 0700, the files 0600, and that no temp file is left.
- `TestRefreshAfterRejection`: two refreshes of the same refused token make one request, with a form body. A refusing endpoint gives a `*TokenError` and leaves the file.
- `TestAccountsWithoutAStoredLogin`: the API key, both proxied kinds, an unknown account and an account that is not logged in. No file is made.
- `TestLoginThroughTheBrowserCallback`: the Codex flow against a local authorize and token endpoint. The endpoint checks the code verifier against the challenge the authorize request carried.
- `TestLoginWithAPastedCode`, `TestLoginRefusesAnotherLoginsState`: the Claude manual flow.
- `TestLoginAccountsLogout` (`src/cli/login_test.go`): the three commands from the argument list to the files.

The local endpoints are servers the tests run. They are not recordings of the real endpoints.
