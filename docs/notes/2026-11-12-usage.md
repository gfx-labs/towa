# `towa usage` reports a subscription's limits

2026-11-12

## Why

A subscription account stops answering when a limit is used up, and nothing in towa said how close an account was. jcode reads both providers' usage endpoints for its `/usage` command.

## What the endpoints hold

Read on 2026-11-12 with the stored logins.

- Anthropic, `GET https://api.anthropic.com/api/oauth/usage`, with the headers of an OAuth request. Named windows (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`), each null or `{utilization, resets_at}` with the utilization in percent. A `limits` list repeats them and adds the limits of one model (`kind: weekly_scoped`, `scope.model.display_name`), which have no key of their own. No plan name.
- ChatGPT login, `GET https://chatgpt.com/backend-api/wham/usage`, beside the Codex base URL. `plan_type`, and `rate_limit.primary_window` and `secondary_window`, each null or `{used_percent, limit_window_seconds, reset_at}` with `reset_at` in Unix seconds. The response also names the user (`email`, `user_id`, `account_id`), which towa does not read.
- An API key has no subscription on either provider (`provider.ErrNoUsage`), and no request is sent for one.

## Decision

- `provider.UsageReporter` is one call, `Usage(ctx, credential)`, implemented by the Claude and Responses clients. It returns the plan and a list of limits: a name, the percent used and the reset time.
- A limit keeps the provider's own name where it has one (`seven_day`, `weekly_scoped Fable`). A ChatGPT window has only a length, so it is named by it (`7d`, `5h`).
- `towa usage` lists every `oauth` and `proxied_oauth` account of a provider that reports usage, sorted by id. `--account` picks one, and `--json` prints an array.
- An account whose usage cannot be read is printed with the reason, the others are still printed, and the command exits with an error.
- Nothing is cached and nothing reads usage during a turn. jcode polls Anthropic at most every 15 minutes, as a caution of its own. A command a person runs is not a poll.

## Check

```
$ towa usage
ACCOUNT  PROVIDER  PLAN    LIMIT                USED  RESETS
a-ant    claude    -       seven_day            46%   2026-11-17T22:59:58-06:00
a-ant    claude    -       weekly_scoped Fable  76%   2026-11-17T22:59:59-06:00
gfx      codex     promax  7d                   77%   2026-11-17T01:24:44-06:00
gfx-ant  claude    -       seven_day            100%  2026-11-15T06:59:58-06:00
gfx-ant  claude    -       weekly_scoped Fable  24%   2026-11-15T06:59:59-06:00
```

`gfx-ant` at 100% matches the rate limit it has been answering with. `towa usage --account nope` exits 1 with `account "nope" is not configured`.

`TestUsageReadsTheSubscriptionsLimits` in each provider package replays a recorded response.

## The recorder and a secret split across reads

Recording the ChatGPT response failed without a message: the test passed and no file was written. One of the four values to redact (the email, the two ids, the credit balance) lay across two reads of the body; which one was not checked. The recorder replaced secrets one chunk at a time, then refused to write when one was left in the joined body, and returned that refusal as a read error at the end of the body, where the JSON decoder had already finished.

`redactChunks` now replaces a secret in the whole body and cuts it back into the same number of chunks. A boundary inside a secret moves to the end of its replacement. The refusal stays as a check that nothing is left. `TestRecordingReplacesASecretSplitAcrossTwoReads` covers it.
