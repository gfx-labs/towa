# Store: directory backend, recovery, fork and listing

2026-11-11

## Backend and contract

`src/store/dir` implements `store.Store`. Each session is self-contained:

```
<root>/<id>/meta.json              metadata, including opaque caller state
<root>/<id>/log.jsonl              plain framed JSON lines, or
<root>/<id>/log.jsonl.zst          the JSON lines in zstd frames
<root>/<id>/blobs/<sha256>         stored tool output
<root>/<id>/torn-<offset>-<suffix> bytes set aside by Repair
<root>/.index/children.json       derived data, not needed to move a session
```

Everything a session needs moves with its directory. `TestMovedSessionContinues` copies only that directory to a different root, starts a second process with no shared memory, loads its context and full history, opens its blob and appends an entry. Both log formats are covered. The second process's configured compression need not match the session's: a session keeps its original format.

Ids and entry times come from the caller. Metadata `Updated` is the time of the last stored entry, read from the log, not rewritten each turn. `SetMeta` replaces Title, Model, Mode, Dirs, Archived and State, not identity, parent, cwd or Created. Rewriting metadata on every append would cost a file write, fsync, rename and directory fsync without adding information.

### Whole or absent, and recovery

Each `Append` is one encoded buffer, one write and one fsync. Both formats frame the whole append:

- Plain: entry JSON lines followed by `{"commit":{"entries":N,"bytes":B}}` and a newline. Lines after the last commit are uncommitted, even when each entry line is whole. They are never yielded as stored entries.
- Zstd: one zstd frame between two copies of a 24-byte marker. Each marker is a zstd skippable frame, holding the compressed length, entry count and a compaction flag. `zstd -dc log.jsonl.zst` prints the JSON lines, checked with the installed zstd 1.5.7. The markers allow backwards traversal and skipping records without decompression.

A crash can leave a prefix of an append. `Load` and unbounded `History` yield the previously committed entries followed by `*dir.TornError`, which matches `store.ErrTorn` through `errors.Is`. `Append` refuses a torn log. `Repair(ctx, id)` is on the interface: it durably writes the torn bytes under a unique name, syncs the directory, truncates the log to the last complete append and syncs the log. Repeated repairs at the same offset keep every set-aside file. No operator command or import of `dir` is needed by the session layer.

The original plain format had only entry lines, so a tear between two lines could silently keep half an append. It was replaced, not retained as a compatibility mode. This is pre-milestone storage. An old unframed plain log is reported as torn, not silently imported or assumed committed.

An append write failure truncates to the previous size and syncs the rollback. The real-backend regression test uses `RLIMIT_FSIZE`, temporarily ignoring `SIGXFSZ`: the write becomes a short write followed by `EFBIG`. The log is byte-for-byte unchanged afterwards and another append succeeds. Removing the truncate made this test fail in both formats. A failed fsync itself was not induced, and the rollback cannot promise durability if its own truncate or sync also fails: those errors are returned together.

### Load, history and compaction

`Load` finds the latest compaction by walking backwards and reads it plus entries after it. The plain format examines lines backwards. The compressed format walks the markers and decompresses from the latest record flagged as holding a compaction. A provider's opaque JSON or a tool's input may have a `compaction` key, so a candidate entry is decoded to distinguish it from a compaction item. There is no Snapshot method or separate snapshot file.

`History` reads any positional range of all committed entries. Compressed records before the range are skipped by their counts. The plain format reads lines from the start. There is no plain offset index.

The sequence opens its file when ranged over and reads up to the committed end observed by the call, so later appends are not half seen. Damage that fails JSON decoding or zstd decompression is reported as a `CorruptError` with a file and offset.

### Stored content and forks

`PutBlob` hashes while writing a temporary file, fsyncs it, renames it to the digest and fsyncs the directory. The first creation of `blobs/` also syncs the session directory. An existing digest is deduplicated. `OpenBlob` accepts only `sha256:` plus 64 lowercase hex digits, returns `store.ErrNotFound` for missing content, and hashes as the caller reads. A read to the end reports a digest mismatch as `CorruptError`, not EOF. Reading only a prefix provides no complete-hash verdict.

The transcript contract was extended by the coordinator: a `Part.Stored` references the full output while a neighbouring text part carries the preview the model gets.

ACP schema 1.31.0's fork request has no point-in-history field. `Fork(ctx, source, meta)` copies all committed source history and keeps its entry ids and log format. The caller supplies the new session's complete metadata, including any copied or changed state. A torn source gets `ErrTorn` and must be repaired first. The source's shared log lock holds off appends during the copy.

The fork's log is copied. Immutable blobs are hard linked when possible. `EXDEV`, `EPERM` and `ENOTSUP` switch to copying and fsyncing the content. Deleting either session leaves the other complete. The fork test checks independent histories and blob access after deleting the source. A Linux test puts a source session on `/dev/shm` and links its directory into a root on btrfs, exercising real `EXDEV` and verifying the copied blob still opens after source deletion. There is no stand-in filesystem.

`Meta.Archived` and `Filter.Archived` implement any / exclude / only. The store's zero filter is any. ACP's omitted archive filter is exclude, which the session layer selects explicitly. Archive does not prohibit loading or appending.

`Meta.State []byte` is opaque. It is base64 in metadata JSON, and is returned byte for byte even for non-text, invalid UTF-8 or non-JSON bytes. The store does not know what session configuration it holds. `SetMeta` replaces it; `Fork` uses the bytes in the caller's new Meta rather than choosing inheritance rules.

### Locks and leftover directories

Calls touching a session lock its log with `flock`. Create, Fork, Delete, Sweep and index construction also take a root directory lock. The order is always root before log, never log before root. Appending to unrelated sessions does not take the root lock. A root namespace lock also stops two Creates of the same id from removing each other's staging directories.

Create and Fork build `.<id>.creating`, fsync its files and directory, rename it to the id and fsync the root. Newly created ancestors of the configured root have their parent directories synced too. Delete first renames to `.<id>.deleting`, syncs the root, then removes it while retaining its locks. The canonical id is therefore whole or absent after a crash.

`(*dir.Store).Sweep(ctx)` is **on demand at startup**, not at `New` (which does no I/O). It removes only names of the staging forms with valid ids and no held directory lock. A running build or delete is not swept. The directory-lock check is tested on real files. The coordinator wires startup invocation; it is not on `store.Store`, since these names are specific to dir.

## Append and read measurements

Machine: i9-14900, Linux 6.12, btrfs on NVMe (TEAM TM8FP4004T), mounted `rw,relatime,ssd,discard=async,space_cache=v2`. Other lanes were building concurrently. The size and operation counts are repeatable, but fsync times varied substantially with system activity.

Workload: 2000 turns, each a prompt, five tool calls (reasoning with a 256-byte random signature, call, 4000-byte result), answer and usage. 18 entries and about 31 KiB a turn, 36000 entries and 58.9 MiB total. Text is cut from the installed Go 1.27.3 `net/http` tree (158 files, 3.1 MiB), not a hand-built provider recording. The seeded corpus workload is synthetic coding-session traffic, not a recorded real session. Reads are medians of five on fresh store values and warm filesystem caches.

```

TOWA_STOREBENCH_ROOT=$JCODE_SCRATCH_DIR \
TOWA_STOREBENCH_TURNS=2000 TOWA_STOREBENCH_TOOL_CALLS=5 \
TOWA_STOREBENCH_RESULT_BYTES=4000 TOWA_STOREBENCH_KEYWORD=RoundTripper \
```

Do not read the 11.8 vs 2.18 ms as a compression CPU speedup. Before plain framing, the same workload measured 1.88 ms mean for plain and 2.17 ms for zstd, with p50 1.76 vs 1.96 ms. The final compacted p50 was 1.85 vs 2.08 ms. The consistent cost of compression is about 0.2 to 0.3 ms per turn at those sizes, smaller than the fsync variance.

One append per entry costs 18 appends and fsyncs a turn. In the final run plain took 44.9 ms mean per turn, 60.2 MiB on disk and a 1.022 written/payload ratio. Zstd took 43.1 ms, 29.0 MiB and a 0.492 ratio. Full-history scan was 287 vs 575 ms. The loop should batch appends by turn or step, not entry.

Zstd stays the default: about 2.9 times smaller session directories, roughly 1.8 MiB of encoder/decoder heap once per Store value (not per session), and about 0.2 ms extra p50 append cost. History scans can be appreciably slower, and one frame per tiny entry compresses less. The encoder and decoder are made lazily. `WithLowerEncoderMem` measured only about 0.3 MiB less heap, within run-to-run variance, so it is not set. Re-measure on recorded real sessions once available, especially image-heavy sessions.

## List: measure first, then page and index

The original List opened every metadata file and the last record of every log, even for a Cwd or ParentID filter. Each page repeated that work. The measurement creates real sessions through Create and Append on persistent roots of 1000 and 10000 sessions, with one small committed zstd append each. One in 100 has the selected Cwd and ParentID. Every measured call checks its result count.

```
TOWA_STOREBENCH_LIST_ROOT=$JCODE_SCRATCH_DIR/store-list \
nice -n 10 go test -v -count=1 -run TestListByHand -timeout 20m ./src/store/storebench/
```

The test reuses those roots for before/after comparisons. The caller removes them afterwards. Timings below are medians of three. **File-data-cold** means POSIX_FADV_DONTNEED on every file before each sample. Directory entries and inode caches remain warm: dropping those needs privilege, which was unavailable. These are not boot-cold or fully cold filesystem measurements.

| sessions | full result filter | before warm / data-cold | after warm / data-cold | matches |
|---|---|---|---|---|
| 1000 | all | 25.3 / 34.0 ms | 24.5 / 32.2 ms | 1000 |
| 1000 | Cwd | 27.4 / 33.1 ms | 12.5 / 15.3 ms | 10 |
| 1000 | ParentID | 26.1 / 36.3 ms | 0.230 / 0.406 ms | 10 |
| 10000 | all | 258 / 316 ms | 248 / 325 ms | 10000 |
| 10000 | Cwd | 245 / 318 ms | 99.8 / 149 ms | 100 |
| 10000 | ParentID | 243 / 314 ms | 2.52 / 3.89 ms | 100 |

The unfiltered full result has no speedup, as expected. Its cost and the children cost at 10000 justify changes:

1. `Filter.After` is an exclusive id cursor and `Filter.Limit` is a caller-supplied match limit (zero unlimited, negative invalid). Directory names give sorted id order before metadata is read. The filter applies before the limit. A cursor still works after its session is deleted. Session code can request page size plus one to decide whether a next page exists.
2. A Cwd/archive mismatch is rejected from metadata before opening or decoding the log. Cwd remains a scan, not a second index.
3. Parent lookup uses `.index/children.json`, mapping parent ids to sorted child ids. It is derived, tagged with root directory mtime, and rebuilt when a session directory arrives, leaves or is renamed, including when copied from another root. Create, Fork and Delete mutate the namespace under its lock. Append and SetMeta do not invalidate it because ParentID is immutable. An index is never required for Load or to move a session.

Initial index construction is measured separately with warm files: 27.1 ms at 1000 sessions, 126 ms at 10000. A later namespace change makes the next parent query rebuild once, so a workload that creates a session between every parent query still pays that scan. No per-create persistent index update was added.

After, first page with Limit 50:

| sessions | filter | warm / data-cold | matches |
|---|---|---|---|
| 1000 | all | 1.80 / 1.93 ms | 50 |
| 1000 | Cwd | 9.92 / 13.7 ms | 10 |
| 1000 | ParentID | 0.234 / 0.396 ms | 10 |
| 10000 | all | 4.71 / 5.46 ms | 50 |
| 10000 | Cwd | 51.2 / 71.4 ms | 50 |
| 10000 | ParentID | 1.12 / 2.15 ms | 50 |

The paging test exhausts multiple pages with Cwd, archived and parent filters, compares to unbounded List, deletes a cursor, changes membership by Create/Delete, copies directories into new and already-indexed roots and removes the derived cache to force reconstruction. A corrupt cache is reported, not silently accepted. Removing the derived cache allows rebuilding it.

## Review fixes: blob publication and bounded history

A visible blob name is not proof that its publisher has synced the rename. A concurrent PutBlob used to acknowledge an existing hash before that publisher synced the blobs directory. Similarly, a call finding an existing blobs directory could return before its creator synced the session directory. Each PutBlob now syncs the session directory, writes and syncs its own temporary file, renames it over the hash and syncs the blobs directory. It never relies on another call's durability acknowledgment. Duplicate content still leaves one final copy, but incurs a write and three syncs per call. The append benchmarks above do not include blob traffic.

The real-backend blob regression checks that a duplicate publication performs its own file and namespace syncs through the existing counters. This is not a power-cut experiment. History's bounded-range regression extends every torn prefix in both formats: a bound satisfied by intact entries stops normally, while a bound beyond the intact history, including a From beyond EOF, reports ErrTorn. The previous implementation hid the error for every nonzero To. Both regressions fail against the original source through a Go build overlay, without changing the shared checkout. Repair and retained torn files are unchanged. All scoped checks listed above pass after the fixes.

## Not done or not checked

- No actual power cut or killed writer. Cutting every prefix checks parsing and recovery, not what a filesystem physically persists.
- No induced fsync failure, nor successful durability in a system where both the original operation and rollback sync fail.
- No macOS execution, and no fully cold directory/inode-cache measurement.
- No garbage collection of unreferenced blobs, and no offset index for the plain format, as requested.
- No SQLite or Postgres backend. No filesystem assumptions about advisory locks on network filesystems have been tested.
- Cwd filtering remains a metadata scan. The children index rebuilds after a namespace change. A manually edited ParentID that changes only meta.json is outside the store contract and does not invalidate it.
- Concurrent copying into a live root without taking its lock is not an import transaction. Finish the copy before querying it.
- The harness does not measure blobs. Source-derived synthetic sessions are not recorded real session measurements.
