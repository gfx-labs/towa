## Decisions

- **The loop holds no session state.** A turn reads the conversation from the store and appends to it. So the store is required, and the loop creates the store session when `Load` returns `ErrNotFound`.
- **A call is stored before it is dispatched.** The response's items are appended, durably, before any tool runs. A process that dies in between leaves a call with no result. The next turn's `Conversation` gives it the `unknown` outcome and stores that. It is not run again. A call without a result anywhere but the end of the log is an error, not something to patch.
- **Outcomes after a cancel** (`Settle`): a tool that returned a result keeps its outcome, also after a cancel, because it knows what it did. A tool that returned an error after a cancel is `unknown`, except a read-only tool, which is `cancelled` because it cannot have had an effect. A call that never started is `cancelled`.
- **Scheduling** (`Conflicts`): an executing call runs alone. A writing call that names no paths is treated the same. Two calls that write one path run in the model's order. A call does not overlap a write of a path it lists in its `Locations`, so a read after a write in one response sees the write. `src/tools/batch` uses the same rule through the loop's `batch.Plan`, including `ReadPaths`.
- **The dispatcher waits for every tool to return**, also after a cancel. It relies on a tool stopping when its context ends. There is no timeout after which the loop gives up on a tool, because nothing configures one.
- **Calls of a response that does not end with `tool_use`** (cut off, failed, `max_tokens`) are not run. Each gets a `cancelled` result.
- **Limits.** `max_tool_calls` is checked per call: calls up to the limit run, the rest get a `cancelled` result that names the key, and the turn ends. The token limits and `max_wall` are checked before each model request, and `max_wall` is also a deadline on the turn's context, so a tool that runs past it is cancelled. Cached tokens count towards `max_input_tokens`. A limit is the most a turn may use: the turn stops when it is used up, and the request that crosses a token limit is not cut short.
- **Updates and store writes use a context that is not cancelled**, so a cancelled turn still tells the client how its calls ended and still records them.
- **A failed update ends the turn** with the error. The model is not sent further requests for a client that is gone.
- **Router.** A request is retried or moved only while its response has yielded nothing. After the first event the client may have been shown text, so a failure is returned. A refused credential gets one `auth.Source.Refresh` per entry before the policy is asked. The router sets `Usage.Account` when the provider left it empty. The error it returns has a `*router.Failed` in its chain naming the entry, which is where `Stop.Account` and `Stop.Model` come from.
- **Moves** reach the loop through `router.WithReport(ctx, …)`, because `provider.Provider.Stream` has no other channel. The loop logs each and sends retries and fallbacks as a `session_info_update` carrying `harness.Move`.
- **Policy.** `Retry` class: wait `RetryAfter` or until `ResetAt`, whichever is later, with no jitter, or else the backoff. A wait above `limits.retry.max_retry_after` counts as retries used up. Used-up retries move to the next entry only for `rate_limit`, `auth` and `overload`. A chain of one returns a rate limit at once.
- **Hooks.** `prompt` runs before anything is stored, and a deny returns `*loop.StopError` with kind `denied`, wrapping `*loop.DeniedError`. `pre_tool` runs after `Permit` allowed the call. A changed input goes through repair and validation again, and one that fails is a failed call. `post_tool` is skipped after a cancel, since its failure would replace an outcome that must stand. A `stop` deny is appended as a user message and the turn goes on, at most `limits.max_stop_denials` times, then the turn ends with a `limit` stop naming that key.
- **Mapping.** A cancelled or unknown call is shown as `failed`: ACP has no other status. A `usage_update` is made only when the model's context size is known. `Part.Stored` gives no content.

## Defaults and their source

| key | default | source |
|---|---|---|
| `limits.max_tool_calls`, `max_wall`, `max_input_tokens`, `max_output_tokens` | 0 (off) | the sketch in `docs/design.md` |
| `limits.max_stop_denials` | 3 | chosen. Nothing upstream bounds it and nothing was measured |
| `limits.retry.max_retries` 2, `initial_backoff` 500ms, `max_backoff` 8s, `jitter` 0.25, `max_retry_after` 60s, `multiplier` 2 | | the retry policy of the Anthropic and OpenAI SDKs, from memory. Not re-read from their sources today |

The design names `max_input_tokens`, `max_output_tokens` and `max_stop_denials`.

## Follow-on changes

- `Options.Resolve(ctx, Turn.Model)` is called once per turn. The resolver owns the default model, router, dialect tools, context size, output maximum, effort and interruption text. No model configuration is duplicated in the loop.
- `Turn.Limits` replaces the loop's limits when non-nil. `Turn.ParentID` is validated as a UUID when a store session is created and saved as its parent. An existing session's parent is unchanged.
- `Result.Final` is the joined text items of the last model response. `Spend(ctx, usage)` lets tools that run child models charge the parent's token limits safely while other tools run. Child logs own their usage entries, so the parent does not duplicate them.
- `BatchDispatcher(ctx)` supplies the batch package with the same validation, repair, permission, hooks, gate and shared tool-call budget as top-level calls. `Plan` refuses a nested batch. The dispatcher records plans and removes each when run, so it cannot dispatch it twice.
- A paused response is sent back unchanged, with no extra user item. It passes through the normal limits check before the next request.
- A direct or wrapped `auth.LoginRequiredError` becomes an `auth` stop. A `models.NoModelError` becomes a `request` stop before any provider call, preserving the original typed cause. Resolver failures pass through `StopFor`, so the CLI can return `acpharness.stop` rather than only a generic RPC error.
- `src/loop/looptest` builds an actual Chat Completions client, one-entry router and directory store, with a small read tool on `fsops`. It is a test tool, not a dialect adapter. The bounded recorder allows two requests for a read turn and one for an unknown-model 404. Replay tests check stored entries, ACP updates after JSON, final text, usage, cancellation and typed stops.

- The complete turn was recorded from local Ollama 0.24.0 with `llama3.2:3b` on 2026-11-11. Five inference requests were made in total. The first two-request attempt ended with tool syntax as text, so the system prompt was made explicit about answering from the one read result. That attempt was replaced by the successful two-request recording. The other request recorded the unknown-model 404. No model was pulled and no credential was read.
- The recording demonstrates our chat parser and loop reading a real local server's stream. It does not establish behavior for another provider's native tools, errors, headers, reasoning or limits.
- Offline replay passes for the complete read turn, mid-text cancellation, unknown-model typed stop, the per-turn input-token limit and bounded stop hook. A prompt denial runs real hooks and proves the resolver and store are untouched. The assertions cover the stored parent chain, tool result, final text, client-visible tool metadata and updates after JSON, and usage totals.
- Kept these contract-boundary tests plus the direct real-file dispatcher tests. Removed cancellation scaffolding that added no distinct proof.

- `Current(ctx)` carries the current copied turn and its loop through tool dispatch, including effective limits and serialized update callbacks, without a process registry. `Result.Usage` remains populated when a turn fails after recorded usage, allowing a child wrapper to charge successful and failed children.
- `Options.NewCompactor` constructs or retrieves the session's `compact.Controller`. Preparation reads the full append-only history, repairs interruption state, applies the controller's effects in one append, then renders `compact.Items` before `ConversationWithRole`. Native automatic compaction is normalized at its stream position. Compaction usage counts against turn limits before another main request. A completed ACP compaction update carries only the plaintext summary.
- `router.WithPrepare` runs before each selected chain entry, with its credential and actual wire model. Nested summary routers mask that callback. Optional `Entry.Preparation` supplies the selected context window, output maximum, system blocks and interruption role/text. Non-nil metadata requires positive allowances. `provider.ContextNamer` supplies canonical opaque identity from the actual selected credential, not a configured provider alias. The actual request's model and credential account are passed as `transcript.Origin` to compaction rendering and control, so unknown legacy provenance does not authorize native replay.
- One further local Ollama main request was authorized and recorded after replaying the existing real summary exchange. Total local inference requests by this lane are six. `TestCompactedTurn` replays the old real read turn, starts the real summary client on the original full history, appends a new user message while summary work is pending, and continues the actual loop against the new main recording. It checks unchanged old entries, the new user's `FirstKept`, no tool redispatch, client compaction completion, combined summary/main usage and `end_turn`. Offline `-race -count=5` passes. No new summary call, external credential or model pull was used. The summary runs through a real router with a request allowance above the selected entry's maximum; replay verifies that the endpoint cap applies without replacing the checkpoint system prompt.
- Kept the recorded compaction acceptance and one direct selected-entry preparation regression. No scaffolding test was committed.

- Terminal return calls `Controller.Finish` once with the last actual selected request identity and full current history, before the wall-time context is canceled. It appends only effects already ready at that snapshot, then takes the final usage total. It does not start another request or wait for a normal summary completion. Ready failures join the turn's existing error. Pending work is canceled and joined by `Close`, including canceled turns.

## Remaining gaps

- A provider's paused response is not covered by a recording. Router retry waits, move reports and credential refresh are still untested through a turn. The turn's wall deadline has no whole-turn test.
- Real provider-native compaction account paths remain untested. The recorded compaction exchange is local Ollama emulation, not proof of another provider's opaque behavior.
- Rate-limit state shared per account in process (design, "Accounts and fallback") is not built: each request starts at the chain's first entry.
- Legacy routers without `Entry.Preparation` retain the resolver's first-entry context size. Runtime wiring must fill metadata for every actual entry.
- The interruption text comes from the resolver. Texts for calls the loop answers itself are in `history.go` and are the loop's own wording, not a dialect's.
- No telemetry spans or metrics in the loop.
