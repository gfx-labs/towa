# ACP json v2 and extension methods

2026-11-11. Work is on branch `acp-layer`, rebased onto master after its stored-session and conformance additions. Listener ownership moved to the auth lane (`src/listen` and `src/config/listen.go`), so this lane does not implement listeners or CLI wiring.

## Implemented

The generator, generated types and dispatch, connection, sides, errors and acptest use `encoding/json/v2` and `encoding/json/jsontext`. Raw parameters and results are `jsontext.Value`. Generated codecs use `MarshalJSONTo` and `UnmarshalJSONFrom`. Outbound envelopes are written once with `json.MarshalWrite`, not marshaled once for their payload and again for their envelope. Inbound newline frames are decoded before releasing their storage, and asynchronous handlers retain decoded copies.

The ACP exclusion was removed from `.golangci.yml`'s depguard rule. This is the only change outside the assigned ACP/generator paths and this note. No caller needed a mechanical RawMessage edit. No dependency was added: bytebufferpool was already pinned.

### Compatibility decisions

The connection sets deterministic object ordering, JS escaping and v1's nil-slice/nil-map formatting. Generated optional field tags were classified by Go shape and checked against schema properties:

- 321 optional slices/maps keep `omitempty`: nil and empty are omitted.
- 270 optional scalar, pointer and interface fields use `omitzero`: false/zero is omitted, but nonnil pointers to empty values and nonnil interfaces remain present.
- Eight optional value structs have no omission flag, as v1 always emitted them: `AgentCapabilities.{Auth,McpCapabilities,PromptCapabilities,SessionCapabilities}`, `ClientCapabilities.{Auth,Fs}`, `InitializeRequest.ClientCapabilities`, `InitializeResponse.AgentCapabilities`.
- 39 always-written collection fields have no omission flag. Explicit schema defaults, notably `InitializeResponse.AuthMethods: []` and `ElicitationSchema.Properties: {}`, are filled in their generated codec. Other nil collections retain v1's `null`, rather than silently changing caller output to `[]` or `{}`. These nil values violate the schema's nonnullable required collection contract, as they did before. Fixing caller validation is a separate protocol change, not part of this byte-preserving migration.

Named array union variants retain the same nil-as-null connection option. Optional nullable collections remain omitted when nil.

Old custom codecs HTML-escaped their contents even though the enclosing connection disabled HTML escaping. Their v2 replacements keep that distinction. Object unions retain the old sorted `map[string]any` roundtrip, including its rounding of integers above 2^53. ContentBlock also retains upstream's discarded metadata and annotations. Removing those defects or the map conversion would change wire bytes. The tempting direct-struct union optimization was therefore rejected. Sorting is explicit inside the union codec, so direct callers such as session replay receive stable output without having to pass deterministic options.

Input semantics deliberately adopt v2's exact member-name matching, duplicate-member rejection and invalid-UTF-8 rejection. Syntax errors use `errors.As` with `jsontext.SyntacticError`, not unstable error text. Wrong shapes still produce Invalid request. Response encoding failures produce an Internal error only before any bytes are written, and write failures are surfaced rather than followed by a second partial response.

## Measurements

Go 1.27.3, Linux amd64, Intel i9-14900, `GOMAXPROCS=1`, five runs. Entries are medians: ns/op, B/op, allocs/op. All variants use the same final benchmark source. Baseline source is the benchmark-only revision before the serializer move. The unpooled v2 variant uses a Go overlay that replaces only the current connection's pooled reader/writer with `ReadBytes` and `bytes.Buffer`; codecs and compatibility options are identical.

| Case | v1 | v2 unpooled | v2 pooled |
|---|---:|---:|---:|
| Encode session/update | 12897 / 4257 / 59 | 10144 / 4377 / 53 | 8458 / 2560 / 42 |
| Encode prompt | 162820 / 85574 / 83 | 92640 / 84658 / 69 | 74209 / 56616 / 62 |
| Decode session/update | 8161 / 2504 / 26 | 5270 / 1272 / 12 | 5447 / 952 / 11 |
| Decode prompt | 142350 / 56247 / 54 | 94636 / 46822 / 41 | 91644 / 34247 / 33 |

Bytebufferpool adapts its shared size classes across runs. Pooled prompt encoding ranges from 51459 to 60190 B and 60 to 63 allocations. Prompt decoding ranges from 34247 to 48352 B and 33 to 37 allocations. Every pooled case reduces allocations relative to the identical unpooled v2 code. Small-notification decoding has a modest time increase in these runs, but saves 320 B and one allocation. Both paths are retained on the requested bytes-or-allocations criterion.

Prompt encoding exercises the request payload and envelope through SendNotification to avoid measuring a request/response roundtrip. Prompt decoding dispatches actual requests with unique IDs and writes their responses, so it includes concurrent dispatch and response overhead. Benchmarks validate every decoded prompt/chunk, not just that Serve exits. The prompt contains an approximately 8 KiB embedded text resource.

## Buffer ownership

Read buffers are acquired per newline frame and assembled with `ReadSlice`, including fragments larger than bufio's storage. No truncation or new arbitrary size ceiling is introduced. Ownership crosses the read channel to dispatch and returns to the pool after decoding. Blank, failed and cancelled reads return their buffers too. Write buffers are acquired for one complete envelope, encoded before the writer lock, then written once under the lock and returned. No session-lifetime buffer or pooled byte reference survives Put.

## Extension and response ordering APIs

Both AgentSideConnection and ClientSideConnection expose:

```go
RegisterExtensionRequest(method string, handler MethodHandler) error
RegisterExtensionNotification(method string, handler MethodHandler) error
SendExtensionRequest(ctx context.Context, method string, params any) (jsontext.Value, error)
SendExtensionNotification(ctx context.Context, method string, params any) error
```

Names must start with `_`. Nil and duplicate registrations are errors. Request and notification registries are separate. Unknown extension requests answer Method not found. Unknown extension notifications are ignored. Registration and dispatch are mutex-protected, and extension handlers follow the existing concurrency and cancellation rules. No CLI wiring is needed for the APIs themselves.

For the session lane:

```go
func AfterResponse(ctx context.Context, fn func()) bool
```

A request handler can enqueue work in registration order on its own goroutine after its response write finishes, before Serve's handler wait completes. Error responses and failed writes also finish that response attempt and run callbacks. The function reports false for nil callbacks, non-request contexts and already-finished responses. Callbacks are not a global barrier against other concurrent request goroutines. Existing Arrival, RequestPermission, SessionUpdate, unstable method assertions and SendRequest cancellation semantics are unchanged.
