# Token use: tool output, default tools and empty results

2026-11-12

## Why

One task (a merged `oku-trade/trade` fix, Claude Opus 5.5 at medium effort, the same rules loaded) was run through acpharness and through pi 1.3.0. Both made the same fix. acpharness used 668k tokens in 11 requests, pi 444k in 9. Every request sends the whole context again, so a token added early is paid for on each later request. Of the 224k difference:

| Cause | Tokens |
|---|---|
| two more requests after the edit (a second lint and the commit, both asked for by the task repo's `AGENTS.md`) | about 137k |
| larger tool results, sent again on each later request | about 53k |
| larger fixed prompt, over the nine shared requests | about 33k |

This note covers the second and third rows. The first is one run per agent and is not acted on.

## Decisions

- `grep` and `glob` name a file under the working directory by its path from that directory. Any other file keeps its absolute path. The file tools already took a relative path from the working directory, and their schemas now say so.
- `read` returns the lines as they are in the file, without a number and a tab before each. The note that more lines remain still gives the next offset. A range that holds only whitespace is reported in words.
- Off by default (user): the `todo` tool (`tools.todo.enabled`, new), the incomplete-todo poke (`limits.max_todo_pokes`, now 0), the `subagent` tool (`subagents.max_depth`, now 0) and `webfetch` (`webfetch.enabled`). `batch` and `conversation_search` stay on. The poke also needs the tool: a turn is not sent back to a list the model cannot change.
- `acpharness hosts` names webfetch as not covered only when it is on.
- A tool result with no content reaches the model as "The tool call returned no output."

## Empty results

A command that prints nothing, such as `true` or a `git commit -q`, returned one part with empty text. The Anthropic client refused it ("a content part has nothing set") and the turn ended with an internal error. Reproduced on `f008223` through `acphost exec` with the prompt "Run the bash command `true` once".

What others do:

- pi 1.3.0: its bash tool returns `(no output)`. Its Chat Completions client also puts `(no tool output)` in a tool message with no text.
- jcode `037163c7b`: bash returns `Command completed successfully (no output)` (`crates/jcode-app-core/src/tool/bash.rs:730`), and read returns `(empty file)`.

Both fix it in the tool. Here it is fixed where the loop settles a result (`loop.Settle`), so it also holds for an MCP tool, an extra and a hook. `loop.Conversation` applies the same rule to a result already stored, so a session that hit the failure can go on.

## Recording

`src/loop/testdata/factory_write_{1,2}.json` hold the tool list and descriptions, so they were recorded again on `openai/gpt-oss-20b` with the command in `2026-11-12-prompt.md`. The first attempt passed, and the replay passed three times.

## Limits

- No task was run again end to end, so the effect on a whole turn is not measured. Numbered lines may have helped the model pick an `offset` for a partial read, and that was not tested.
- pi's skill listing is not smaller than ours: 7.9k tokens against 6.2k for the same 45 skills. It leaves out a skill whose front matter sets `disable-model-invocation: true`. We do not read that key.
- The skill listing and the context files are now 24k of the 30k default prompt. Nothing here changes them.
