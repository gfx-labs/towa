# Assembling a session's tool set

2026-11-11. Package `src/toolset`.

## What it does

`toolset.Assemble(ctx, Input)` returns the `tools.Set` the loop gets and the compiled schema of every tool in it. The order is the dialect's tools, then the extras, then the MCP tools.

The dialect is passed in as a function that returns its tools (`Input.Tools`), with its name beside it. The package imports no dialect, so adding one changes the caller only.

It holds the rules that belong to no single tool:

- Two tools with one name are a `*CollisionError` that says where each comes from. Nothing is renamed: a prompt that names the tool would no longer find it. The MCP tools are checked by `mcp.Manager.Tools`, which is given the names already taken, and a collision there is its `*mcp.NameCollisionError`, which names the server.
- An extra named in `Input.Disabled` is left out, before names are compared, so disabling an extra also removes a collision with it. A name in the list that matches no extra is an `*UnknownExtraError`, so a misspelt name does not leave the extra on.
- When `tools.gate.enabled` is set, the `accept_large_output` member is added to the top-level properties of every tool that has a schema, the MCP tools included. Until now `gate.Split` took the member out of a call but no schema declared it, so a schema with `additionalProperties: false` refused the call that asked for the full result. The member is not added to `required`.
- Every schema is compiled with `repair.Compile`. One that does not compile is a `*SchemaError` with the tool's name, when the session starts and not on the first call.

## Decisions

- The member is added to every tool, not to a chosen list of gated tools. The loop gates every result (`gate.Apply` in `loop.Dispatcher`), so every tool can be withheld. jcode does the same.
- The member's description is jcode's text, `ACCEPT_LARGE_OUTPUT_DESCRIPTION` in `crates/jcode-tool-core/src/lib.rs` at 1jehuang/jcode 037163c7b. No upstream Claude Code or Codex tool has the member, so there is no upstream text to copy.
- A tool that declares its own `accept_large_output` is an error while the gate is on (`ErrAcceptDeclared`). The gate would take the member out of every call before the tool saw it. jcode keeps the tool's own declaration. Here that would hide a tool's argument without saying so.
- A tool with only a native definition (`provider.Tool.Native`, such as Codex's free-text `apply_patch`) has no JSON schema. It gets no member and no compiled schema, and its input is not validated. Its result is still gated, and the model has no way to ask for the full result of such a tool.
- The schema is edited as JSON tokens, so the members keep their order and the text the model is told differs from the tool's own only by the added property.
- `Result.Schemas` is the map `loop.Dispatcher.Schemas` takes. `loop.Schemas` compiles the same set a second time if the caller uses it. The caller should pass this map.

## Tested

`go test -race ./src/toolset/`. The MCP tools come from a real MCP server over streamable HTTP and a real `mcp.Manager`. The dialect and extra tools in the tests are bare `tools.Tool` values with real schemas, since no dialect or extras package exists yet.

- Order, and a disabled extra left out.
- A call carrying the member passes the compiled schema and then `gate.Split`, for a strict schema, a schema with no properties and an MCP server's schema. With the gate off the schema is unchanged and refuses the member.
- Each refusal: extra against dialect, two dialect tools, MCP against dialect, an unknown disabled name, a schema with an unresolved reference, a tool with its own member.
- Checked by breaking the code: with the member not added, all three tests fail.

## Not done

- The extras are not wired. `src/tools/extras` is not committed. Its worker plans one constructor per extra that returns an error wrapping `extras.ErrDisabled` when its own config turns it off. The caller, or a function added here, turns those into `[]Extra`.
- There is no config key that lists disabled extras. `conversation_search.enabled` is planned by the extras worker, `jev.route` empty already means no `jev_decision`, and webfetch, batch and skill have no switch. `Input.Disabled` takes names from whoever reads those keys.
- Nothing calls `Assemble` yet. The session wiring still builds its set itself.
- The Codex dialect's worker exports `codex.Tools(env, cfg, deps) ([]tools.Tool, error)` and `codex.Dialect`. The caller closes over the arguments to make `Input.Tools`. That package is not committed yet, so the two have not been compiled together.
- A model switch that changes the dialect needs a second `Assemble`, which asks the MCP servers for their tools again. Whether the MCP tools should be kept from the first call is open.
