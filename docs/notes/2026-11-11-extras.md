# Extras as tools

Date: 2026-11-11

## Scope

`src/tools/extras` constructs `tools.Tool` values for `conversation_search`,
`webfetch`, `jev_decision`, `skill_manage` and `batch`. Each constructor takes
its capability's configuration and dependencies. No constructor joins a set,
resolves a name collision or adds `accept_large_output`. `src/toolset` owns
those rules. Constructors return an error wrapping `extras.ErrDisabled` for an
off switch, and an error for a missing dependency. Skill takes `config.Context`
and a non-nil skill listing, which may be empty. Jev takes a client and a
credential resolver called for each request, so credentials can be refreshed.
A nil Jev client means that route is disabled.

Switches: `conversation_search.enabled`, `webfetch.enabled`,
`tools.batch.enabled`, `context.skills_enabled`. Jev is absent when `jev.route`
is empty. The conversation search section is in `src/config/convsearch.go`.
The coordinator wires its field, defaults and validation into `config.Config`.

## Sources and differences

All jcode source was read with `git show`, not from its working tree.
The ref is `origin/master` at `8e11eb23e`, except Jev, whose approved source
is `037163c7b`.

Paths below are under `crates/jcode-app-core/src/tool/` in jcode.

- `conversation_search.rs:57-83` supplies query, turns and stats. The adapter
  adds scope and session. `:100-110` supplies the stats heading, not its
  figures: our text reports measured stored entries and recorded usage rather
  than jcode's compaction-manager estimates. Search headings, no-results text,
  ellipses and the omitted-results line follow `:123-153`. Entries are called
  entries rather than turns, and include session UUIDs and field names,
  because positions count transcript entries, not user/assistant messages.
  Range headings follow `:170-183` with that same change. The empty-call
  guidance is `:228-230`. Scope failures and all other added text are ours.
- `webfetch.rs:47-69` supplies the URL field. This adapter deliberately does
  not advertise jcode's format and timeout arguments: the capability accepts
  only a URL, uses configuration's timeout and converts HTML to Markdown.
  It fetches text unchanged. The `Fetched ... (N bytes)` framing is `:172`.
  The truncation guidance follows `:164-165`, but says bytes rather than chars.
  Scheme and HTTP-status errors follow `:77,:96`. Too-large text follows
  `:104` without a declared size, which can be unknown. Invalid URL, timeout,
  network, unsupported content type and parse-failure text are ours.
- `jev_decision.rs:145-173` at `037163c7b` supplies the schema. Options are
  sorted by id before sending. The capability checks limits, appends the
  untrusted-state framing and verifies the answer is an offered choice.
  `:245-251` supplies failure/timeout framing. `:257-262` supplies the success
  JSON: choice, optional confidence, provider. Provider means the configured
  route, not a model id. Invalid-input and unreadable-answer details come
  from the capability and are ours. Timeouts over the configured maximum
  fail instead of being silently clamped as jcode does.
- `skill.rs:54-83` supplies `skill_manage`, name and action. Only load is
  advertised, because that is the implemented capability. `:154-158` supplies
  the loaded skill text and base directory. Name normalization is `:367-373`.
  Unknown-name text follows `:143` and adds available names. Empty-name text
  follows `:368`. Too-large text is ours. There is no list/reload/read action.
- `batch.rs:14-39` supplies the schema with sibling arguments, tool and intent.
  `maxItems` comes from configuration, not jcode's fixed 10. It does not
  implement jcode's undocumented nested-parameters aliases. `:316,:335,:353`
  supply headings, error prefix and completed counts. The adapter keeps the
  complete child Parts instead of jcode's `50000 / count` truncation. Child
  output already passed through the loop's gate. Batch's final output passes
  through that gate too. Failed child results count as failed, even when
  the child returned no Go error. Unknown and cancelled outcomes are retained.

## Conversation bounds

`convsearch.Limits.HitBytes` was split into `SnippetContextBytes`, `MessageBytes`
and `ToolResultBytes`, so no invented shared default stands in for three
upstream figures. The search window keeps the whole match with the configured
context on each side, rounding inward to whole UTF-8 characters. jcode rounds
outward, which may exceed the byte figure by part of one character.

Defaults and sources in `conversation_search.rs`:

| Config key | Default | Source |
| --- | ---: | --- |
| `scope` | `descendants` | `docs/design.md` in this repo |
| `enabled` | true | conversation search availability in `docs/design.md` |
| `max_hits` | 10 | `:135` |
| `snippet_context_bytes` | 50 per side | `:306,:310` |
| `message_bytes` | 1000 | `:189` |
| `tool_result_bytes` | 200 | `:201` |
| `max_blob_bytes` | 0 | local opt-in policy, do not read stored blobs by default |

`max_hits` also bounds range entries. Stored blob skips and truncation are
reported in the result. No store listing behavior changed.

## Results and dispatch

Text tools put the same text in `Result.Parts` and `Result.Content`, with
`OutcomeFailed` for typed capability errors. A malformed argument, storage or
file I/O failure, or missing runtime dispatcher is a Go error for the loop to
settle. No error strings are inspected to classify failures.

Batch takes a `func(context.Context) (batch.Dispatcher, bool)` dependency,
normally `loop.BatchDispatcher`. Every child goes through the loop's repair,
validation, permission, hooks, call budget and gate. The parent uses effect
`Executes`, so it does not overlap outer calls that its children could conflict
with. In ask mode this can ask permission for the parent as well as children.
Nested batches are rejected. Batch keeps all child Parts for the model and
uses `loop.ToolResult` to retain child-specific ACP Content, including diffs,
or convert their Parts when no separate Content exists. This imports the
loop's existing converter rather than duplicating it.

`accept_large_output` is injected by `src/toolset`, not extras. In jcode it is
added centrally by `crates/jcode-tool-core/src/lib.rs:36-76`,
`ensure_intent_in_schema`. Here toolset rejects an existing declaration, because
`gate.Split` consumes that member before the capability sees it.

## Buffer measurement

Conversation output is assembled in a bytebufferpool buffer and copied to the
result string before Put. `BenchmarkConversationSearch` runs the whole tool
against a real directory store containing ten matching entries. It checks the
outcome and match count before timing. Three runs with `-benchmem` on this
Linux/amd64 i9-14900 checkout compared a strings.Builder overlay with the
pooled implementation. The benchmark and inputs are otherwise unchanged.

| Implementation | ns/op (three runs) | B/op (range) | allocs/op |
| --- | --- | --- | ---: |
| strings.Builder | 194635, 156571, 175747 | 355106-355222 | 188 |
| bytebufferpool | 163282, 166175, 183102 | 351860-352060 | 181 |

The allocation reduction is repeatable in these runs. The timing ranges
overlap, so this is not evidence of a throughput improvement. This measures
store reads and formatting together, not the buffer alone.
