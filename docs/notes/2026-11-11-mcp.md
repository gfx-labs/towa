# MCP lane: client, meta-tool, direct tools, OAuth

2026-11-11

## What was built

- `src/mcp/server.go`: `Server`, and `Servers(cfg, sessionServers, lookupEnv)`, which merges `mcp.servers` with a session's `mcpServers` by name.
- `src/mcp/manager.go`: `Manager`, one per session. `ListTools`, `CallTool`, `Connected`, `Close`. A connection starts on first use and closes after `mcp.idle_close_seconds` without a request.
- `src/mcp/stdio.go`, `proc_linux.go`, `proc_darwin.go`: the stdio transport, with the server as the leader of its own process group.
- `src/mcp/http.go`: the per-server HTTP client, a copy of the client from `src/httpclient` with the round trip wrapped to add the server's headers and its token.
- `src/mcp/tools.go`: `Manager.Tools(ctx, taken)`, which returns the direct tools and the `mcp` tool as `tools.Tool` values.
- `src/mcp/oauth.go`: `TokenStore`, the token source with refresh, and `Login`, by browser callback or by a pasted address.
- `src/mcp/mcptest`: the protected MCP server the OAuth tests of `src/mcp` and `src/cli` run against.
- `src/cli/mcp.go`: `mcpCommands(h Host)`, with `mcp login <server> [--manual]` and `mcp logout <server>`.
- `src/config/mcp.go`: the `mcp` section.

## Decisions

- **A session's server replaces a configured server of the same name whole.** Transport, URL, headers and the direct flag all come from the session. The configured entry's `direct` and headers do not carry over, so a configured secret header is never sent to a URL the client chose. The replaced server keeps its place in the order.
- **Direct by default for session servers, not for config servers.** `mcp.session_servers_direct` (default true) sets the first, `mcp.servers[].direct` the second.
- **A name collision is `*NameCollisionError` from `Manager.Tools`.** It covers two direct servers with the same tool name and a direct tool with a name in `taken`. The `mcp` tool's own name being taken is an error too. `Tools` connects to the direct servers to read their tools, so the session lane calls it once at session start. A direct server that cannot be reached fails the session start for the same reason.
- **Direct tools are fixed at session start.** A server that announces a tool list change later updates what `mcp` search sees, not the session's direct tools. Changing the tools mid-session would break the prompt cache.
- **The `mcp` tool lists only servers that are not direct.** It is left out when every server is direct. `search` matches every word of the query against name and description, case-insensitively, name matches first, and returns schemas for the first `mcp.search_results` (default 10) and only server and name for the rest, under `more`. A server that cannot be reached is reported under `unavailable` and the search still answers.
- **Effect.** A tool is `tools.Executes` unless its server has `trust_annotations` and the tool declares `readOnlyHint`. The annotations are a server's word about itself. Session servers are trusted by default (`mcp.session_servers_trust_annotations`), config servers are not. The `mcp` tool is always `Executes`, because `tools.Tool.Effect` is per tool and not per call.
- **A call is never sent twice.** A failure before the request is sent is `OutcomeFailed`. A JSON-RPC error from the server is `OutcomeFailed` with its message. Anything else after sending is `OutcomeUnknown`. The one exception is a 401: the server did not act on it, so the HTTP request is sent once more with a refreshed token.
- **The stdio transport is ours, not the SDK's `CommandTransport`.** The SDK signals only the process it started, so a server run through `npx` or a shell would leave the real server running. Ours sets `Setpgid`, and on close does stdin close, wait, SIGTERM to the group, wait, SIGKILL to the group, with `mcp.terminate_grace_seconds` (default 5, the SDK's value) for each wait. The group is also killed when the server's stdout ends, so children do not outlive a server that exits on its own. The framing is still the SDK's `IOTransport`.
- **A stdio server starts in the session's working directory** (`Options.Dir`) with the harness's environment plus its own variables. Its stderr goes to the log at debug level.
- **No default HTTP client.** `NewManager` fails for a remote server without `Options.HTTPClient`, and a client whose transport is unset is refused, since net/http would read that as its default transport. `TestEveryTransportListsAndCalls` checks that the number of requests the server received equals the number that went through the client it was given.
- **The connect timeout is applied by hand.** The SSE transport keeps its event stream on the context passed to `Connect`, so that context must outlive the connect. `mcp.connect_timeout_seconds` (default 30) and the caller's cancellation are attached for the connect and detached after initialize.
- **OAuth.** `Login` uses the SDK's `AuthorizationCodeHandler` for discovery, registration, PKCE and the code exchange, and listens on `mcp.oauth.callback_addr` for the redirect. After login the SDK's handler is not used: it keeps tokens in memory, and we need them in the store and refreshed under a lock shared by processes. `serverTransport` sets the bearer token on each request. A refresh takes `LockMCP`, re-reads, and refreshes only if the stored token is still the stale one.
- **A stored login is tied to the URL it was issued for.** If the server name now has another URL the token is not sent.
- **`*LoginRequiredError`** is returned when a server answers 401 and nothing can fix it without a person. Its text names `acpharness mcp login <server>`. A turn never starts a browser login. The model is told the server needs a login.
- **A dead refresh token is recorded.** When the token endpoint refuses a refresh with `invalid_grant`, `invalid_client` or `unauthorized_client` (RFC 6749 section 5.2), `RefreshRejectedAtUnixMs` and `RefreshRejection` are saved in the server's file under the lock, as the auth lane does for accounts. While they are set no refresh is sent, by this process or another, and the stored access token is not sent either. A new login writes the file without them. Any other refresh failure (network, 5xx) is not recorded and is tried again.
- **Manual login.** `--manual` prints the authorization page and reads the address the browser ends on. The redirect is still a loopback URL, on a port picked by binding `mcp.oauth.callback_addr` and closing it, so nothing answers there and the user pastes the address from the browser's address bar. The SDK checks the pasted state against the one it sent.
- **The mcp commands act only on servers in `mcp.servers`.** A session's servers are not known to the command line. A name that is not configured, or names a stdio server, is refused before any request. `logout` deletes the file under the lock and revokes nothing.
- **Spans.** `Options.Tracer` gets `mcp.connect` and `mcp.call` spans with `mcp.server`, `mcp.transport` and `mcp.tool`. A call span also has `mcp.tool.is_error` when the server answered. A failed span has status Error and `error.type` (`error` or `login_required`), without the error's text, because a server's refusal can quote what it was sent. The connect span is a child of the call that caused it. Nil means no spans.
- **Refresh sends a public client's id in the form.** Left to detect the style, `oauth2` first tries basic auth, and that failed attempt consumed the single-use refresh token in the test.
- **MCP features not used:** sampling, elicitation, roots, resources, prompts. A tool result that asks for more input is reported as a failed call.

## Tests

Both ends are the real protocol. The stdio server is the test binary run again with `ACPHARNESS_MCP_TEST_SERVER` set, serving the SDK's `Server` over `StdioTransport`. The HTTP servers are the SDK's `StreamableHTTPHandler` and `SSEHandler` on `httptest`.

```
nice -n 10 go test -race -count=3 ./src/mcp/
nice -n 10 golangci-lint run ./src/mcp/... ./src/config/...
GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./src/mcp/... && go vet ./src/mcp/...
CGO_ENABLED=0 go build ./src/mcp/...
```

- `TestEveryTransportListsAndCalls`: list, call, a tool error, an unknown tool, an unknown server and use after close, on all three transports.
- `TestIdleConnectionClosesAndReopens`: all three transports. For stdio it checks the first process and its child are gone and a new process answers.
- `TestCallInFlightHoldsTheConnectionOpen`.
- `TestCloseKillsTheStdioProcessGroup`: a server that exits on stdin close and leaves a child, and one that ignores stdin close.
- `TestServerThatDiesIsStartedAgain`, `TestConnectTimeout`, `TestMissingCommandIsAnError`, `TestRemoteServerNeedsAClient`.
- `TestSessionServersWinByName`, `TestServersThatCannotBeUsedAreErrors`.
- `TestDirectAndMetaTools`: a configured remote server behind `mcp` and a session stdio server that is direct, through `tools.Set`.
- `TestDirectToolNameCollisionIsAnError`, `TestSearchReportsAServerItCannotReach`.
- `TestCallThatGetsNoAnswerIsUnknown`: a stdio server whose tool writes a file and exits without answering. The call's outcome is `OutcomeUnknown` and the file exists, so the call did take effect. A call that could not be sent is `OutcomeFailed`.
- `TestOAuthLoginAndRefresh`: streamable HTTP and SSE, with `auth.Store` on a temp directory. Login, use from a new manager, refresh after the token is revoked, a moved URL, a refused refresh that is recorded and not sent again (the token endpoint's request count stays at 2), and a new login that clears the record.
- `TestOAuthManualLogin`: the page is read from what `Login` prints and the redirect address is pasted. An address with another login's state is refused and the stored login is unchanged.
- `TestSpansNameTheCallAndCarryNoContent`: the four spans of one connect and three calls, their attributes and parent, and that no span holds the argument text.
- `TestMCPLoginLogout` (`src/cli/mcp_test.go`): the commands from the argument list to the token file, by browser and with `--manual`. An unknown or stdio server is refused with no request sent to the server.

**What the OAuth tests do not prove.** The MCP side and the bearer token check are the SDK's (`RequireBearerToken`, the protected resource metadata handler). The authorization server in `src/mcp/mcptest` is hand-written: metadata, dynamic registration, the code grant with a PKCE check, and single-use refresh tokens. The SDK has one, but in an internal package, and no real one can be reached from a test. These tests show that our client completes that exchange and stores what it is given. They do not show how a real authorization server words its metadata, what it requires at registration, or what its error bodies look like. That needs a login against a real server, by hand.

## Not done

- `mcpCommands` is not registered in `cli.go` yet, so lint reports it as unused until the coordinator wires it.
- Not wired into a session. See the requests below.
- Nothing was run against a real remote server (Linear, GitHub). No live check exists and no credentials were used.
- A manual login with a pre-registered client needs `mcp.oauth.callback_addr` set to the registered port. With port 0 the redirect URL changes on every run, which only dynamic registration accepts.
- The unknown outcome is tested over stdio only. Over HTTP a dropped connection takes the same path in `run`, and no test drops one.
- Connections are per session. The design says a config server may be marked shared across the sessions of a listener. Not built.
- No span for listing a server's tools, only for connect and call.
- No before and after benchmark for the one pooled buffer (`jsonResult`). It follows the buffer rule for a tool's output, but it is not a measured hot path.
- macOS: builds and vets. Nothing was run there.
