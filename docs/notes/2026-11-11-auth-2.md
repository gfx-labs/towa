## MCP token storage

Agreed by message with the `mcp` lane, which declares the interface in `src/mcp` and does the refresh itself:

```go
type TokenStore interface {
    LoadMCP(server string) (auth.MCPTokens, error) // errors.Is(err, auth.ErrNotLoggedIn) without a file
    SaveMCP(server string, t auth.MCPTokens) error
    DeleteMCP(server string) error
    LockMCP(ctx context.Context, server string) (unlock func() error, err error)
}
```

- Files are `<auth dir>/mcp/<name>.json` and `.lock`. They use the same code as an account's files: directory 0700, file 0600, temp file and rename, `flock` on a lock file that is never removed.
- The key is the server's name. A server from `session/new` is named by the client, so the name can hold a slash, a space or a leading dot. Any non-empty name is accepted, and `<name>` in the file name is the hex SHA-256 of it. The hash is a plain file name for any input and keeps names apart that differ only in case, which matters on macOS. The file holds the name, and a file whose stored name differs is an error.
- `MCPTokens.ServerURL` is compared with the configured URL by the `mcp` lane after loading. The store does not know the configured URL.
- `TokenEndpoint` was added at the `mcp` lane's request: the SDK gives the token URL only at the code exchange.
- The files cannot be listed by server name, since a hash does not give the name back. Nothing needs that yet. `accounts` does not show MCP logins.

## Dead refresh tokens

- A refresh that the token endpoint refuses with `invalid_grant`, `refresh_token_invalidated` or `unauthorized_client` writes `refresh_rejected_at_unix_ms` and `refresh_rejection` into the account's file, under the lock. The tokens stay in the file.
- While the record is set, `Credential` and `Refresh` return `*auth.LoginRequiredError` and send nothing. The check is made before the lock and again after it, so processes that were waiting on the lock send nothing either. The error text names the `login` command to run.
- `login` writes a whole new file, which has no record. `logout` deletes the file.
- The codes are the OAuth codes among jcode's permanent markers (`crates/jcode-base/src/auth/refresh_state.rs`). jcode also matches phrases in the error text, such as "token has been revoked". Those are not matched here: the code is read from the `error` member, either the string itself or the `code` of an object.
- Any other failure (network, a 5xx, a refusal with another code) leaves no record and is tried again on the next call.
- A dead record does not expire. Only a login clears it.
- The loop maps errors to stops. `*auth.LoginRequiredError` should become an auth stop, and that mapping is the `loop` lane's.

## Embeddings

- `embed.New(embed.Options{Config, HTTPClient, Credentials})` and `(*Client).Embed(ctx, inputs) ([][]float32, error)`.
- The request is `POST <base_url>/embeddings` with `model`, `input` as a list, and `dimensions` only when it is not zero. `encoding_format` is not sent, so the answer is lists of numbers.
- Inputs go out in requests of at most `embeddings.batch_size`, one after another. An error in any request fails the call and returns no vectors.
- Vectors are placed by the `index` of each item, not by their order in the answer. A missing, repeated or out-of-range index, a count that differs from the inputs, an empty vector, vectors of different lengths, or a length other than a configured `dimensions` is a `*embed.ResponseError`.
- A status other than 200 is a `*embed.Error` with the status, the `type`, `code` and `message` of the `error` object, and `Retry-After` in seconds when present.
- With `embeddings.account` empty no `Authorization` header is sent. With it set, the credential comes from an `auth.Source` and is sent as a bearer token.
- No retry. The caller decides.
- Config defaults: `base_url`, `model` and `account` empty (no endpoint), `dimensions` 0, `batch_size` 32, `timeout_seconds` 120. 32 is the default of `--max-client-batch-size` in Text Embeddings Inference, the sidecar the design recommends. The README of `https://github.com/huggingface/text-embeddings-inference` gives it (read on 2026-11-11, main branch). No TEI server was run. 120 seconds is not measured: the one data point is the recording run below, where a cold model load and two requests took 46 s.
- `Embeddings.validate` does not check that `account` names a configured account, because it sees only its own section.

### The recordings

`src/embed/testdata/embeddings_ok.json` and `embeddings_unknown_model.json` were recorded with `providertest.Recorder` from the Ollama 0.24.0 server already running on this machine, with the chat model `llama3.2:3b` (3072 numbers per vector). The coordinator approved it. No key, no download, two requests:

```
TOWA_EMBED_RECORD_URL=http://127.0.0.1:11434/v1 TOWA_EMBED_RECORD_MODEL=llama3.2:3b \
  go test -count=1 -run '^TestRecord$' ./src/embed/
```

The files hold `127.0.0.1:11434`, a date header and no host name, user name or path.

They prove the wire shape as Ollama serves it. They prove nothing about OpenAI's own errors, its handling of `dimensions`, or its rate-limit headers.

## Checks

```
nice -n 10 go test -race -count=1 ./src/auth/ ./src/embed/
nice -n 10 golangci-lint run ./src/auth/... ./src/embed/...
GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./src/auth/... ./src/embed/...
```

- `TestMCPTokenStorage`: names with a slash, a leading dot, a space and a case difference each get their own file in the one directory, modes 0700 and 0600, the lock excludes a second holder and not another server's.
- `TestRefreshAfterRejection`: after an `invalid_grant`, a new source and the old one both return `*LoginRequiredError` and the endpoint's request count does not move. Saving a new login makes the account work.
- `TestRefreshIsTriedAgainAfterATransientFailure`: a 503 is tried again and leaves no record.
- `TestEmbedReplaysARecordedAnswer`, `TestEmbedReportsARecordedRefusal`: the client's requests match the recorded ones and its results match the recorded answers.
- `TestEmbedRefusesAVectorOfAnotherLength`: the recorded answer against a configured length of 8, and against one input.

## Not done, not checked

- Batching over more than one request has no test. It needs a second recording with other inputs, and the allowance was two requests.
- `dimensions` sent to a server that honours it. Ollama was not sent one.
- A request with an account: the `Authorization` header is untested.
- `Retry-After`, a 429 and a 401 from an embeddings endpoint. The parsing of `Retry-After` is untested, and a date form of the header is not read.
- An index out of order, repeated or missing in an answer. No real server was seen to send one, and no answer was written by hand to test it.
- OpenAI, TEI, llama-server and the other endpoints the design lists. Only Ollama was contacted.
- `encoding_format: base64`, a smaller answer than lists of numbers. Not built, and the saving is not measured.
- Nothing ran on macOS.
- `refresh_token_invalidated` and `unauthorized_client` are in the list from jcode's source. Only `invalid_grant`, from the local test endpoint, was exercised.
