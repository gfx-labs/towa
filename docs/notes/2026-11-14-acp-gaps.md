# ACP gaps closed, 2026-11-14

An audit against the ACP schema (go-acp v0.1.2, schema 1.31.0) and the reference adapters (zed-industries/codex-acp and claude-agent-acp, main on 2026-11-14) found four places where towa did less than the protocol offers. All four are fixed.

## embeddedContext

`promptCapabilities.embeddedContext` is advertised. Anthropic and Responses already carried a text resource as `<resource uri="...">` text. Chat Completions now does the same (`resourceText` in `src/provider/chat/request.go`). Live check: a Haiku turn given an embedded resource repeated the secret word and the file path inside it.

## Retry and fallback

A provider retry or fallback was reported under `_meta.towa.move`, which no client reads. It is now a `notice` update with severity `warning`. Its title reads like "rate_limit on X, retrying in Ns" or "... falling back to Y", and its description is the provider's message. It is sent only to a client that advertises `session.notices`, as the gate does for every update behind a capability. `harness.Move` and `loop.MoveFor` are gone. `_meta.towa` now carries only the typed stop.

## MCP elicitation

- go-acp v0.1.1 had no `sessionId`, `toolCallId` or `requestId` on `CreateElicitationForm` and `CreateElicitationUrl`. Its generator dropped the members of a variant's nested `anyOf` scope. go-acp 88ca4f7, tagged v0.1.2, merges them as optional fields: a pointer where the type has no zero to omit (`RequestId`, a union). `IdleStateUpdate` gained the `error` member it was missing for the same reason.
- towa sets `ClientOptions.ElicitationHandler` and `ElicitationCompleteHandler` on a session's own MCP connections when the client advertises `elicitation`. A server is told only the modes the client advertised. It forwards the request as `elicitation/create` with the session id and maps accept, decline and cancel back.
- `toolCallId` is not set. go-sdk v1.8.0 gives a handler no link from a server request to the client call it came from.
- A shared server (`mcp.servers[].shared`) is held by the pool for every session, so its connection takes no elicitation.
- On MCP protocol 2026-07-28 a server asks with an `InputRequests` result (SEP-2322), not a standalone `elicitation/create`. go-sdk's client middleware sends those to the same handler, so both reach the client.
- Live check, Haiku with a stdio server whose tool asks for a name with a form: an accepting client got an `elicitation/create` with `sessionId`, and the tool returned `action=accept name=Ferdinand`. A declining client gave `action=decline`. Without the capability the server got `client does not support elicitation (-32602)` and the tool failed with that text.

## Terminal auth

- A client that sets `clientCapabilities.auth.terminal` gets one `terminal` auth method per OAuth account whose provider has a login flow: id `login-<account>`, args `login <provider> --account <id>`. claude-agent-acp does the same with `--cli auth login`. codex-acp offers agent-type methods only.
- The client appends args to its launch command. kong parses `towa --config x.yaml login claude --account a --manual`, which printed the authorize page in a check against a scratch HOME. `towa serve login ...` fails with "unexpected argument login", so a client that wants terminal auth starts towa without naming `serve` (it is the default command).
- `authenticate` still answers invalid params: the spec says a client must not pass a terminal method to it, and towa has no agent-type method.
