# The harness prompt: autonomy, no terminal, tool guidance per request

2026-11-12

## Why

The prompt was compared with jcode's (`crates/jcode-base/src/prompt/system_prompt.md` at 037163c7b) and pi's (`packages/coding-agent/src/core/system-prompt.ts` and `core/tools/*.ts`, `earendil-works/pi` main on this date). Ours said nothing about three things the others cover:

- When to ask. A session in a worker pool has nobody reading it, so a question ends the work. jcode says so. We did not.
- That a command has no terminal. `src/tools/shell` gives a command no standard input and no terminal, so an editor, a pager or a prompt for input fails or hangs until the timeout. Neither the prompt nor the `bash` description said it.
- Which tool to use for what. The tools section was one fixed paragraph that named no tool. Pi builds its rules from the enabled tools.

## What changed

- `agentctx.Instructions` has a paragraph on working to the end of the task: ask only for a decision that is the user's, otherwise take the reasonable option and say which, fix a failure and do not stop at reporting it.
- `tools.Tool` has `Guidance`, lines for the system prompt. Core tools take them from `guidance` in `src/tools/core/specs/<name>.json`. Extras set them where the tool is built.
- The tools section is `agentctx.ToolGuidance` followed by the lines of the tools the request offers, in the tools' order. `src/cli/runtime.go` builds it for each chain entry, because the tool set differs per entry: an entry with hosted search is sent the provider's `web_search` in place of `websearch`, and its line names that tool.
- The no-terminal rule is the `bash` tool's guidance line and is repeated in its description. It is in the prompt only while `bash` is offered.
- Descriptions were rewritten for `jev_decision`, `skill_manage`, `subagent`, `batch`, `webfetch` and `conversation_search` to say what the tool returns and when to use it. Each statement was checked against the code that runs the tool.
- The `rules` section is removed. It was a slot in `agentctx.Prompt` for the harness's own rules, added with the prompt builder and never filled: the runtime passed no text for it, so it was never in a prompt. The lines that would have gone there now belong to the tool they are about.

## The factory write recording

`src/loop/testdata/factory_write_{1,2}.json` hold the prompt, so they were recorded again. Three things changed in `TestFactoryWriteProcess`:

- The model is `qwen3.8-27b` (`factoryModel`), served by LM Studio on a machine with a 32 GB GPU. With the new prompt `llama3.2:3b` on the local Ollama wrote a trailing newline once and no file twice in five recordings. `openai/gpt-oss-20b` passed six of six and `qwen3.8-27b` eight of eight.
- LM Studio there keeps one model loaded. While another client was asking for a different model, two recordings failed before the second request with `Failed to load model ... Engine protocol startup was aborted`: each load request aborted the other's. That is the server being shared, not the model. Record when nothing else is using it, or run it again.
- The server is named by `ACPHARNESS_FACTORY_WRITE_UPSTREAM`, no longer fixed to the local Ollama. Its host is given to the recorder as a secret, so the recording holds `http://REDACTED/...` and not the machine's address.
- The prompt asks for the relative path `factory-result.txt`. The first recording with the new model failed on replay: it streamed the absolute path in pieces of a few characters, so the replay could not put the new temporary directory in place of the recorded one, and the write went outside the working directory. With a relative path the model's reply holds no directory. The recorded root is now read from the prompt's working directory section.

## Not done

- No line about hesitating before an irreversible action. jcode has one. Ask mode covers it for a client that wants to be asked, and auto mode is the choice to not be asked.
- MCP tools have no guidance lines. Their descriptions come from the server.
- No measurement. The text was judged by reading, not by an eval. `TestPromptToolsSectionFollowsTheToolsOfTheEntry` checks that the section follows the tool set, not that the wording works.
