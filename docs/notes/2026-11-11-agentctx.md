# agentctx: context loading and the system prompt

2026-11-11

## Built

`src/agentctx`:

- `LoadFiles`: the context files, in prompt order.
- `ListSkills` and `LoadSkill`: skills by name and description, and one skill in full. `LoadSkill` is a plain function for a `skill` tool to wrap.
- `Load`: both of the above plus the sections added by config.
- `Build`: the prompt as `[]provider.SystemBlock`, with the ACP `systemPrompt` applied.
- `Capabilities`: what to advertise under `sessionCapabilities.systemPrompt` (append and override).

`src/config/context.go`: the `[context]` section.

| key | default | meaning |
|---|---|---|
| `agents_files` | `true` | read `AGENTS.md` (and `CLAUDE.md` in the claude dialect) |
| `global_dir` | `~/.agents` | directory of the global file. Empty turns it off |
| `extra_files` | none | read after the instruction files. Each must exist |
| `extra_dirs` | none | every `.md` file under each, in path order. Each must exist |
| `skills_dirs` | `["~/.agents/skills"]` | searched for directories holding `SKILL.md` |
| `max_file_bytes` | `0` (no limit) | largest context file or `SKILL.md` |
| `max_total_bytes` | `0` (no limit) | largest sum of the context files |
| `sections` | none | `{name, text}` or `{name, file}`, added after the built-in sections |

## Decisions

- File order: global `AGENTS.md`, global `CLAUDE.md`, then each directory from the repository root down to the working directory (`AGENTS.md` then `CLAUDE.md`), then `extra_files` in config order, then `extra_dirs`. The file nearest the working directory is last among the instruction files, so the most specific one is read last.
- The repository root is the nearest directory upwards with a `.git` entry (a directory, or the file a worktree or submodule has). Found with `Lstat`, without running git. Outside a repository only the working directory is searched: walking to `/` would read files the session has nothing to do with.
- A missing `AGENTS.md` or `CLAUDE.md` is not an error, since most directories have none. Everything else is: a permission error, a dangling symlink, a non-regular file, invalid UTF-8, a missing extra file or directory. Errors wrap `*fs.PathError` with the path.
- A file reached twice (a `CLAUDE.md` symlinked to `AGENTS.md`, or an extra file that is also an instruction file) is read once, at its first position. Compared by resolved path.
- Limits default to none. No measurement gives a size, and a limit fails the session, so a guessed default would break working setups. Over a limit is a `*LimitError` naming the file and the config key. Nothing is truncated.
- The global file is in `~/.agents`, which is where `skills_dirs` already pointed in the design sketch. It is a config key, so a host can point it elsewhere.
- A skills directory that does not exist holds no skills: the default one is absent on most machines. A `SKILL.md` that is unreadable, has no front matter, or lacks a name or a description is an error. Pi skips these with a diagnostic. Here a bad file is reported.
- A skill name found in a later skills directory is left out, the earlier directory wins. The same name twice in one directory is an error, because nothing says which one was meant.
- The search does not go into a skill's own directory or into dot directories, and follows symlinks with a visited set.
- Front matter is parsed with `go.yaml.in/yaml/v3`, which koanf's YAML parser already brings in. Descriptions use folded scalars often enough that a hand-written parser would be wrong.
- Section names: `prompt`, `tools`, `rules`, `project_context`, `skills`, `working_directory`, the configured ones, `client`. A section with no text is left out. A configured section cannot use a built-in name.
- `append`: the client's text is the last section, `client`.
- `override`: the client's text replaces `prompt`, `tools` and `rules`. Project context, skills, working directory and configured sections stay: the schema says workspace and environment context may still be included, and configured sections are the operator's, not built-in defaults. The tool definitions, MCP servers and permissions are not in the prompt at all, so `Build` cannot change them.
- Any other mode is `*UnsupportedModeError`. Empty content, or a block that is not text, is `*ContentError`. Text blocks are joined with a blank line.
- The upstream prompt, the tools text and the rules text are parameters of `Build`. Nothing upstream is written in this package. The few sentences `Build` writes itself are the skills list heading, the "Contents of <path>" line and the working directory line.
